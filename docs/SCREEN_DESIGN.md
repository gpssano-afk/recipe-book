# 画面・操作設計

状態：Phase 1AのS01/S03/S04/S05と保存済み検索を実装。Phase 1Bの写真・お気に入り一覧S06とタグ絞り込みを実装。履歴・Web検索・設定機能は未実装。今回の範囲は[ROADMAP](ROADMAP.md)を参照。[機能仕様](PRODUCT_SPEC.md) / [データ](DATA_MODEL.md) / [テスト](TEST_PLAN.md)

入力上限と保存ルールはPRODUCT_SPECを正本とする。以下の「保存」はDBのトランザクション完了を指す。

## 1. 共通UI

- 画面幅360〜430 CSS pxを主対象に、320pxでも横スクロールせず操作できる。幅768px以上ではコンテンツ最大960px、カードは2〜3列。スマホでは1列。
- 背景は生成り `#FFF8EE`、本文は濃茶 `#33251F`、主要ボタンは赤茶 `#94432E` と白文字。補助色に落ち着いた緑 `#48644B`。色だけで状態を伝えない。実装時にコントラスト4.5:1（通常文字）を測定する。
- システム日本語フォントを使用し外部フォントを取得しない。本文16px以上、入力欄16px以上、タップ領域48×48px以上、操作間隔8px以上。アイコンに日本語ラベルを添える。
- 下部ナビは「ホーム」「レシピ」「ルーレット」「設定」の4つ。定番と検索はホーム・一覧から1タップ。現在位置を文字・形・色で表示する。
- 主要操作は下部の親指が届く場所に置く。セーフエリアと固定ナビの高さ分の余白を設け、最後の項目・エラー・キーボードを覆わない。
- 登録/編集では下部ナビを隠し「キャンセル」「保存」の固定操作列へ切替。ソフトキーボード表示時も入力欄と主要操作を見失わないようスクロールできる。
- 編集・削除をスワイプや長押し専用にしない。ドラッグの代わりに行の「上へ」「下へ」で順番を変えられる。
- 見出し、label、button、リスト、ダイアログを意味のあるHTMLで構成する。フォーカスを可視化し、ダイアログはフォーカストラップ・閉じた後の復帰を行う。保存結果はaria-liveで通知する。
- 過度なルーレット演出はしない。0〜300msの切替のみ、`prefers-reduced-motion` では即時。抽選結果がアニメーション終了に依存しない。

## 2. ルーティング・遷移

GitHub Pagesの再読み込み404を避けるためhashルーティングを使う。

| 画面ID | パス（`/recipe-book/` に続く） | 入口・主な出口 |
| --- | --- | --- |
| S01 ホーム | `#/` | 定番、検索、追加、ルーレット、設定、詳細 |
| S02 ルーレット | `#/roulette` | ホーム/下部ナビ → 結果詳細/決定 |
| S03 レシピ一覧 | `#/recipes` | 下部ナビ → 詳細/追加/検索/定番 |
| S04 レシピ詳細 | `#/recipes/:id` | 一覧/定番/履歴/結果 → 編集/調理履歴入力 |
| S05 登録・編集 | `#/recipes/new`、`#/recipes/:id/edit` | 一覧/詳細/検索 → 保存後の詳細、取消で元画面 |
| S06 お気に入り一覧 | `#/favorites` | ホーム/一覧 → 詳細/追加 |
| S07 レシピ検索 | `#/search` | ホーム/一覧 → 詳細、外部ブラウザ、URL登録 |
| S08 設定・バックアップ | `#/settings` | 下部ナビ/警告 → 出力/復元、復元後ホーム |

```text
ホーム ─┬─ ルーレット ─ 抽選結果 ─ これに決定 ─ 決定履歴
        ├─ 佐野家の定番 ─┐                            └─ 作った入力
        ├─ レシピ一覧 ──┼─ レシピ詳細 ─┬─ 編集 ─ 保存/取消
        ├─ 保存済み検索 ─┘              └─ 調理履歴 ─ 追加/編集/削除
        ├─ Web検索 ─ 外部ブラウザ ─ 戻る ─ URL登録
        └─ 設定 ─ 復元ファイル選択 ─ 検証 ─ 上書き確認 ─ 復元 ─ ホーム
```

戻る操作はブラウザ/Androidの戻るを尊重する。直リンクで履歴がない詳細からは一覧に戻す。編集中の画面内遷移・戻るでは「入力を破棄しますか」を表示し、維持を初期選択にする。ページ離脱は `beforeunload` も補助的に使うがOS終了時の確認は保証できない。未知のルートは「画面が見つかりません」とホームへのリンクを表示する。

## 3. S01 ホーム

```text
┌ 佐野家のごはん                 設定 ┐
│ [レシピを検索]                      │
│ 今日、何を作る？                    │
│ [献立ルーレットを回す]              │
│ 佐野家の定番               すべて → │
│ [写真 料理名] [写真 料理名]         │
│ 最近決めた料理 / 最近作った料理     │
│ [レシピを追加]                      │
│ バックアップの案内                  │
└ ホーム / レシピ / ルーレット / 設定 ┘
```

| 観点 | 仕様 |
| --- | --- |
| 表示情報・構成 | 定番を更新日降順に最大4件、決定履歴を最新5件、調理履歴を最新5件。各「すべて」で履歴シートを開く（20件ずつ追加表示） |
| 操作・遷移 | カードで詳細、検索でS07、追加でS05、ルーレットでS02、定番でS06。決定行の「作った」で調理日入力シート |
| 入力チェック | 通常はなし。調理入力はS04と同じ検証 |
| 保存・キャンセル | 閲覧自体は保存なし。シートの保存で履歴追加、キャンセルで無変更。決定履歴取消には確認を出す |
| データなし | 「最初のレシピを登録しましょう」。定番0件は星の使い方、履歴0件は各用途を説明。未実装Phaseの項目を完成機能と表示しない |
| エラー | DB読込失敗は空表示の代わりに再試行。バックアップ時期の案内は閉じられ、設定から常に再確認できる |

履歴シートには日時、料理名、詳細へのリンク、調理記録の編集/削除または決定の取消を置く。全体履歴への追加ページは作らない。

## 4. S02 献立ルーレット

上からカテゴリ選択、お気に入り限定、タグ選択、最近の調理除外、候補件数、結果カード。下部に「抽選する」、結果表示後は「再抽選」「これに決定」を置く。

| 観点 | 仕様 |
| --- | --- |
| 表示情報 | 適用中の条件、候補数、結果の写真/料理名/調理時間/カテゴリ、詳細へのリンク |
| 操作・遷移 | カテゴリは1つ、タグは複数選択。結果カードでS04。決定後は完了表示と「作った」「別の料理を選ぶ」 |
| 入力チェック | 条件値が許可値か確認。最近除外はOFF/3/7/14/30日。候補条件はR08参照 |
| 保存・キャンセル | 抽選・条件変更では保存なし。「これに決定」のみ決定履歴を保存。戻ると未決定結果を破棄 |
| データなし | レシピ0件は登録へ、条件結果0件は条件解除を表示。1件はその料理を表示し再抽選を無効化 |
| エラー | 保存失敗は結果を保持して再試行。候補が更新/削除されたら結果を無効にして再抽選。保存中は二重操作不可 |

結果決定と調理済みを異なる文言・ボタンにする。詳細を含む別画面へ移動すると未決定結果は破棄し、戻ったら再抽選する。詳細へ進むリンクに「戻ると再抽選になります」と補足する。保存した決定履歴は画面離脱で消えない。

## 5. S03 レシピ一覧

| 観点 | 仕様 |
| --- | --- |
| 表示情報・構成 | タイトル/件数、検索入口、カテゴリチップ、タグ選択、並び順、写真付きカード、さらに表示、右下の「追加」 |
| 操作・遷移 | カード→S04、星→定番切替、追加→S05、定番→S06、検索→S07。条件チップを個別解除できる |
| 入力チェック | 選択可能なカテゴリ・タグのみ。未知の条件はエラー表示して解除可能にする |
| 保存・キャンセル | 星の保存完了で表示確定。一覧条件はメモリのみ、再起動で既定へ。閲覧にキャンセル操作なし |
| データなし | DB0件は登録、絞り込み0件は「条件に合うレシピがありません」と解除ボタン |
| エラー | 一覧取得失敗は再試行。サムネイルだけ失敗なら代替画像と「写真を読み込めません」、本文操作は可能。星保存失敗なら元の星を維持 |

スクロール位置・条件は詳細から戻る場合に復元。読み込み中と0件を明確に区別する。

| 観点 | 仕様 |
| --- | --- |
| 表示情報・構成 | 表紙、料理名/星、カテゴリ/タグ、人数/時間、材料、手順、メモ、元URL、添付、登録/更新日時、調理履歴、下部「作った」「編集」 |
| 操作・遷移 | 写真で拡大シート（ピンチ/スクロール、閉じるボタン）、URLは外部ブラウザ、編集→S05。メニューに削除。履歴20件ずつ追加表示 |
| 入力チェック | IDが存在するか。調理シートは調理日・メモのR10制約を適用。空欄の材料/手順は「未登録」と表示 |
| 保存・キャンセル | 「作った」で日付/メモ確認後に保存。履歴編集の取消は変更なし。削除は料理名・関連画像と履歴の削除件数・復元不可を示して確認 |
| データなし | 未知/削除済みIDは一覧への導線。画像なしは代替図、履歴なしは初回記録の説明 |
| エラー | 保存失敗はシート入力保持。削除失敗は詳細を残す。URLの形式不正はリンクにせず説明。オフライン時は外部本文を読めない旨を表示 |

元URLはドメインを見える形で表示し、必要なら全文を展開できる。材料や手順が空でもURL・添付を見られる。履歴編集/削除後に最終調理日を再計算する。

## 7. S05 レシピ登録・編集

```text
戻る          レシピを登録
料理名 *      [                      ]
カテゴリ *    [その他               v]
写真          [選ぶ] [撮影] [画面の画像を添付]
              プレビュー / 表紙 / 削除
人数 [  ]人   時間 [  ]分
材料          [材料名      ][分量      ]
              [+行追加] [まとめて貼り付け]
手順          [1.                    ]
              [+手順] [まとめて貼り付け]
メモ / タグ / 元URL / ☆定番
              [キャンセル] [保存]
```

| 観点 | 仕様 |
| --- | --- |
| 表示情報 | 共通入力項目すべて。必須を文字で明記。材料・手順は追加/削除/上下移動。画像の種別と容量、表紙選択 |
| 操作・遷移 | 手入力を基本に写真・URL入口で対象欄へ移動。貼り付けは別シートで分割結果を編集し「追加」。撮影非対応時は選択へ戻す |
| 入力チェック | PRODUCT_SPEC第2・4・7節。保存時に全件検証し、最初のエラーへフォーカス。エラーを欄の下に置き、上部にも概要 |
| 保存 | 画像処理が完了してから保存可能。成功時S04へ（新規も同じ）。編集ではID・登録日を維持。保存中は操作列を無効化 |
| キャンセル | 未変更なら元画面へ。変更ありなら「編集を続ける」「破棄して戻る」。画像追加・削除も未保存変更として扱う |
| データなし | 新規はカテゴリその他、星OFF、残り空欄。編集対象が消えた場合は保存不可、入力のコピーと一覧へ戻る導線 |
| エラー | DB・圧縮・容量不足・競合は原因別に表示。入力と準備済み写真を保持。メモリ不足/OS終了による保持失敗は保証外 |

カメラは通常のファイル選択と別ボタンにし、`capture=environment` はヒントとして扱う。カメラを強制起動しない。材料の「分量のみ」はその行にエラー、全空行は保存時に除去する。

| 観点 | 保存済みタブ | Webで探すタブ |
| --- | --- | --- |
| 表示情報 | 検索欄、カテゴリ/タグ、件数、R04カード | 料理名・食材の欄、検索語送信の説明、外部検索、URL登録 |

## 10. S08 設定・バックアップ

| 観点 | 仕様 |
| --- | --- |
| 表示情報・構成 | アプリ版/DB版/バックアップ形式版、レシピ/写真/履歴件数、画像容量、ブラウザ容量概算、永続保存状態、最終書き出し要求、消失リスク、出力/復元、PWA更新案内 |
| 操作・遷移 | 出力→ファイルダウンロード。復元→ファイル選択→検証→現データと復元後の件数比較→確認。永続保存の要求は説明後のユーザー操作で実行 |
| 入力チェック | DATA_MODELのファイル検証をすべて通過するまで復元実行不可。不正箇所は例「images[2]：画像形式が不正」と表示 |
| 保存 | 上書き確認チェック後「置き換えて復元」。完了後ホームへ。ファイル生成は「保存先のファイルを確認してください」と案内 |
| キャンセル | ファイル選択取消・検証後取消はDB不変。書込開始後はキャンセル不可、処理中表示。検証中は画面を離れてもDB不変 |
| データなし | 件数0、最終出力なし。空バックアップも出力可能。復元先が空でも内容確認は行う |
| エラー | 不正形式/新形式/容量不足/書込中断を区別。旧データが保持された旨を実際の状態に基づき表示。容量API非対応は「取得できません」とし0扱いしない |

復元確認には、レシピ・画像・決定履歴・調理履歴それぞれの現在/復元後件数、ファイル生成日時、全件置換の説明、「今のデータを書き出す」を含める。ファイル内容からHTMLを表示しない。

## 11. エラーと状態の共通表示

| 状態 | 表示と回復操作 |
| --- | --- |
| 読込中 | 短い「読み込み中」。空状態を先に出さない |
| 保存失敗 | 「保存できませんでした。入力はこの画面に残っています」＋原因/再試行 |
| 容量不足 | 「容量が足りません」＋バックアップ、写真削減への案内 |
| 競合 | 「別の画面で更新されました」＋入力を残したまま再読み込みの確認 |
| 更新待機 | 「新しい版があります」＋保存を終えて更新。未保存中は自動更新しない |
| オフライン | 小さな状態ラベル。使えるローカル機能を塞がない |
| 削除成功 | 一覧へ戻り完了を通知。存在しない詳細を残さない |

エラーはトーストだけで消さず操作箇所にも残す。破壊的操作は主要操作と離し、赤系の文字と「削除」で意味を明確にする。
