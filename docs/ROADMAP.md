## 進め方

初期版はPhase 1〜4の全完了で公開する。各Phaseは小さなPRへ分割し、レビューしてから次へ進む。Phase完了と本番公開を混同しない。PRの自動マージは行わない。

順序は指定の4段階を維持するが、**写真付きバックアップをPhase 1へ前倒し**する。URLフィールドはPhase 1から型・編集に含め、Phase 3では外部検索と登録導線を完成させる。PWAのサブパス方針は最初から決め、実装・公開検証はPhase 4で行う。

## Phase 1：基本レシピブックとデータ保存

### Phase 1の分割と今回の完了範囲（2026-10-13）

今回の依頼に合わせてPhase 1を1A/1B/1Cへ分割する。Phase 1全体の既存要件・完了条件は維持する。

- **1A（実装済み）**：React/TypeScript strict/Vite、npm lockfile、品質確認コマンド、hashルーティング、DB v1の5store、レシピ型と入力検証、原子的なCRUDとrevision/世代競合検出、ホーム/一覧/検索/詳細/登録/編集、確認付き削除、未保存変更確認、手入力の元URL。写真はプレースホルダー、設定・ルーレットは未実装案内。
- **1B（実装済み）**：写真・撮影/スクリーンショット選択、形式/容量検証、端末内圧縮、EXIF方向/透明背景対応、サムネイル、表紙・写真順序・削除、拡大表示、お気に入り操作・定番一覧、複数タグ/定番の絞り込み。DB v1とPhase 1Aのデータを維持。
- **1C（実装済み）**：写真込みバックアップv1、全件検証・プレビュー・確認付きの原子的な置換復元、容量管理・設定画面、永続保存許可、消失リスクとバックアップの案内。DB v1と既存データを維持。Android実機の検証は残る。

1Aでは材料/手順のまとめ貼り付けプレビューとタグ選択による絞り込みは実装しない。タグの入力・表示・検索対象への包含は実装済み。まとめ貼り付けはPhase 3、タグ絞り込みは今回のPhase 1Bで実装した。利用者が今回指定した対象を優先し、後続の完了条件を消さない。

型検査・lint・単体/結合テスト・production build・Chromium試験の記録は[TEST_PLAN](TEST_PLAN.md)に記載する。Android実機は未検証。ブラウザ再起動保持の検証はChromiumプロセスと一時プロファイルで実施する。家庭の本番データ利用は1Cの復元テスト成立後まで禁止する。

実装範囲：

1. React/TypeScript/Viteの最小構成、npm lockfile、型検査/lint/テストコマンド、hashルーティングを整える。Node.jsと各依存の互換性を確認する。
2. domainの型・validator、5storeのDB v1、repository、失敗時の原子性・revision照合を実装する。履歴storeは空でよい。
3. 登録/編集/削除、一覧/詳細、保存済み検索、カテゴリ/タグ、定番、最低限のホームを実装する。
4. 画像選択・撮影導線・スクリーンショット・圧縮・表紙・削除を実装する。文字・URLの手動登録も共通フォームに含める。
5. 設定画面、写真を含むバックアップv1、全件検証・置換復元、容量表示・消失リスク案内を実装する。

完了条件：R01〜R06、R11〜R14とR16のDB関連条件を満たす。再起動でデータが保持され、空の別ブラウザ領域へバックアップから復元できる。壊れたファイルや容量不足で元データが失われない。履歴を持たないバックアップv1を作成できる。

確認テスト：T01〜T08、T13〜T19、T23〜T25の該当範囲。fake-indexeddbの試験に加え、実ChromeでBlob/トランザクションを確認する。写真圧縮・スクリーンショット可読性・バックアップメモリのAndroid試験を早期に開始する。本番データ利用は復元テスト成立後。

### Phase 1Bの今回の完了範囲（2026-10-13）

レシピ・写真・metaの一括更新、写真置換のrollback、6枚/40MiB/非画像8MiBの上限、写真付き新規の同操作再送、写真欠損時の閲覧と編集保護を実装。フォーム・一覧・詳細から定番を操作でき、ホームから定番一覧へ1タップで到達できる。画像変更も破棄確認の対象とする。

バックアップ・復元・容量管理UIは1Cへ残す。Android実機の撮影、画像のメモリ/可読性、ソフトキーボード、TalkBackは未検証。実行した試験のみをTEST_PLANへ記録する。家庭の本番データ利用は引き続き行わない。

### Phase 1Cの今回の完了範囲（2026-10-13）

R12〜R14の設定・バックアップv1・復元を実装。空DBと写真・サムネイル・定番・タグ・日時・両履歴を持つデータを往復できる。形式・未知キー・危険キー・深さ・UTF-8・全入力制約・ID/参照・画像・容量を全件検証し、1件でも不正なら置換しない。復元は確認時の世代を照合し、5storeの単一トランザクションで全件置換する。失敗/取消では旧データを保持する。出力は単一スナップショットで、ダウンロード要求と外部保管の完了を区別する。

容量/API非対応表示、永続保存許可の要求、80%警告、初回の消失案内と閉じられるバックアップ案内を追加した。依存追加・DB変更・PWA公開は行っていない。Chromiumで上限状態を試験し、Android実機のメモリ・端末固有の保存/ダウンロード・OS終了は未検証として残す。一般公開と家庭の本番データ利用の判断は実機確認後に行う。詳細な実行範囲はTEST_PLANのPhase 1C記録を参照。

## Phase 3：ネット検索・URL保存

実装範囲：検索画面のWebタブ、外部検索リンク、URL登録入口、材料/手順のまとめ貼り付け導線の磨き込み、出典・オフライン時の説明。共通フォームや型を重複作成しない。

完了条件：R07を満たし、外部ブラウザで探す→コピー→アプリへ戻る→手動保存の一連の操作が可能。外部ページをアプリが自動取得せず、不正URLを保存・実行しない。URLだけでは外部本文がオフライン保存されないことが分かる。

確認テスト：T05、T06、T20、T24。日本語検索語のエンコード、ブラウザ復帰、外部リンク、オフライン時表示を実機で確認する。検索エンジンのDOMは自動テストの固定対象にせず、自分のリンク生成を検証する。
