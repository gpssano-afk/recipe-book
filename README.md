# 佐野家のごはん — recipe-book

家庭のレシピ、ネットで見つけた料理、自分なりのアレンジを一か所に集める、スマートフォン向けのレシピ管理アプリです。「佐野家の定番」を見つけやすくし、将来は献立ルーレットで毎日の料理選びを助けるPWAを目指します。

**Phase 1C（0.3.0）の開発版です。レシピブック・写真・定番に加え、バックアップ・復元・容量管理を実装しました。PWA・公開用CI・本番サイトはまだありません。**

**この版には家庭の本番データを入力しないでください。写真込みのバックアップ・復元は実装済みですが、Android実機の操作・大容量時のメモリは未検証です。ブラウザのデータ削除・保存領域の解放・端末故障に備え、書き出したファイルを端末外にも保管してください。** アプリ内にも同じ案内を表示します。

## 目的と採用技術

個人開発として開発・運用コストを最小限に抑え、初期版はAndroid Chromeのスマートフォン1台で使います。

- React + TypeScript + Vite
- GitHub Pagesの `/recipe-book/` サブパスに対応するhashルーティング（公開・PWAはPhase 4）
- IndexedDBでレシピを端末内保存。写真・履歴用のstoreもDB v1に用意
- サーバー、ユーザー登録、ログイン、クラウドDB、有料APIは不要

採用ライブラリはReact 19.3.0、React DOM 19.3.0、React Router 7.18.4、idb 8.0.4。Vite 7.3.7、TypeScript 5.9.3（strict）、ESLint、Vitest、fake-indexeddb、Playwrightを開発・検証に使用します。実際のバージョンはpackage.jsonとnpm lockfileで固定しています。追加理由・ライセンスは[DECISIONS](docs/DECISIONS.md#d13-phase-1aのライブラリとhashルーティング)に記録しています。

## 開発・検証コマンド

Node.js 22.12以上（検証環境は24.19.0）とnpmを使用します。

```sh
npm ci
npm run dev
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
npm run preview
```

開発時は `http://localhost:5173/recipe-book/`、previewは `http://localhost:4173/recipe-book/` を開きます。E2Eはビルド済みのdistをローカルで配信します。Chromiumがなければ `npx playwright install chromium` を実行してください。Linuxで `/usr/bin/chromium` があれば自動使用します。別の実行ファイルは `CHROMIUM_PATH=/path/to/chromium npm run test:e2e` で指定できます。開発用キャッシュ先が書込み不可の場合は `npm ci --cache /tmp/recipe-npm-cache` を使用します。

## Phase 1A〜1Cで動く機能

- ホーム：一覧・追加への導線、空状態、データ消失リスクの案内
- レシピ一覧：料理名・カテゴリ・時間、料理名/材料名/タグ/メモの検索、カテゴリ/複数タグ/定番のAND絞り込み、更新順/料理名順、30件ずつの追加表示
- 登録・編集：料理名、カテゴリ、材料と分量、人数、手順、時間、メモ、タグ、元URL。材料・手順の追加/削除/上下移動
- 詳細：全入力情報、登録/更新日時、元URLの安全な別タブリンク、編集・確認付き削除
- 料理名だけの登録、入力上限検証、不正URL拒否、編集キャンセル、未保存変更の破棄確認
- IndexedDBへの原子的な保存・関連削除、recipe revisionとmeta世代による競合検出、再読み込み・ブラウザ再起動後の再表示

料理写真がなければプレースホルダーを表示します。スクリーンショットは表紙にしません。設定ではバックアップ・復元・容量を確認できます。ルーレットは「未実装」の案内画面です。保存失敗時は入力を保持し、DB障害を空データとして表示しません。

DB名は `sano-recipe-book`、DB_VERSION=1、storeはrecipes/images/mealDecisions/cookingLogs/meta。画像はimages内の圧縮済みBlobとして保存し、両履歴storeはPhase 2まで空です。Phase 1Aのデータは移行・削除せず、そのまま読めます。保存成功を表示するのはトランザクション完了後です。失敗・初期化障害で既存DBを自動削除しません。未保存入力の自動永続化は行わず、OSによる強制終了時の保持は保証しません。

## Phase 1Bの写真と定番

- 料理写真・スクリーンショットの選択、任意の撮影導線、端末内圧縮、プレビュー、表紙選択、写真削除・上下移動。詳細では拡大・原寸表示
- 料理写真のみサムネイルを生成し、表示対象カードの表紙だけを読み込み。スクリーンショットがあっても料理写真がなければ表紙はプレースホルダー
- 一覧・詳細・フォームから定番登録/解除。ホームから1タップの「佐野家の定番」一覧。星・カードは保存完了後に更新し、失敗時は保持
- 写真変更を本文・metaと一括保存し、キャンセルでは既存データ不変。入力・準備済み画像を保存失敗時も保持

JPEG/PNG/WebPの静止画のみ、入力1枚20MiB・40MP・各辺16,384px、1レシピ合計6枚まで。SVG/GIF/HEIC・アニメーションPNG/WebP・破損・形式不一致を拒否します。料理写真は長辺1,600px/JPEG、スクリーンショットは長辺2,560px/PNGまたはWebP、保存本体1MiB以内。料理写真のサムネイルは320px/100KiB以内。拡大せず縦横比と向きを保ち、料理写真の透明背景は白に合成します。元画像・元の位置情報等は保存しません。全画像40MiBと非画像8MiBの保存上限を検査します。端末固有のメモリや撮影動作は未検証です。

圧縮済みプレビューを確認して「保存する」で確定します。撮影が使えなければ通常の画像選択を使ってください。画像処理に外部サービス・追加ライブラリは使いません。写真の入力原本は残りません。写真を含むバックアップを設定から書き出してください。Android実機の検証が済むまでは架空データ・自作画像を使ってください。

## Phase 1Cのバックアップ・復元・容量管理

設定 `#/settings` から、写真・サムネイル・定番・タグ・元URLを含む全データをUTF-8 JSONとして書き出せます。履歴配列も含み、Phase 2で操作機能を追加します。DB版とバックアップ形式版は独立したv1のままです。新しい依存ライブラリは追加していません。

1. 「バックアップを書き出す」でダウンロードを要求します。アプリはファイルの保管完了を確認できないので、保存先のファイルを自分で確認し、端末外にも保管してください。
2. 自分の信頼できるファイルを「復元ファイルを選ぶ」で選択します。拡張子だけでは判断せず、JSON・キー・型・URL・日時・ID・参照・容量・base64・画像内容と実際の復号寸法を全件検証します。
3. 現在と復元後の件数・生成日時を確認します。「今のデータを書き出す」で現状を残せます。「バックアップ済み、または全件置換を理解しました」にチェックし「置き換えて復元」で実行します。
4. **全件置換のみ**です。追加・統合・取り消しはありません。キャンセル・不正ファイル・競合・保存失敗では置換しません。書き込みは5storeの単一トランザクションで、commit前の失敗は全体をrollbackします。画像は再圧縮せずバイト列を維持します。

レシピ1,000件、画像6枚/料理・全体6,000枚、各履歴20,000件、画像本体＋サムネイル40MiB、非画像8MiB、JSONファイル64MiBが上限です。設定では件数・容量・最終書き出し要求・永続保存状態を表示します。ブラウザの概算APIが非対応なら「取得できません」と表示します。永続保存の拒否でも利用でき、許可されてもデータ保全は保証できません。

空DBではバックアップの案内を出しません。未出力、または7日以上経過してデータ変更がある場合は、ホーム・設定に閉じられる案内を出します。初回登録後の消失リスク案内は確認するとDBに記録されます。

バックアップは暗号化されません。私的情報の保管・共有先に注意し、公開リポジトリへ置かないでください。オリジンやブラウザが変わる場合は旧環境で出力して、新環境で復元してください。Android実機、端末故障、実際の容量枯渇・OS強制終了の検証は残っています。

## データについて

データは利用端末のブラウザ内に保存します。ブラウザデータの削除、端末故障、保存領域の自動解放等で失われる可能性があり、永続性は保証できません。**写真を含むバックアップ・復元は実装済みですが、Android実機の復元・大容量時のメモリは未検証です。一般利用前の開発版として、家庭の本番データは入力せず、架空データ・自作画像で確認してください。** 保存先はオリジン（プロトコル/ドメイン/ポート）ごとに異なるため、devとpreview、別ブラウザや別プロファイル間ではデータを共有しません。入力データ・写真をGitHubや外部APIへ送信しません。
